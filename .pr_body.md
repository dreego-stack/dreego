## Problem

The CI test run takes ~20 minutes. The `main-push` workflow called `task test` twice, and `pull-request-check` ran `go test -race` (135s), coverage and `task test` (238s) separately — the same suite three times over. The `_tests/` layout was also flat (`_tests/go/*.go`, one 145-file package) with a `_tests/fixtures` reference-app scaffolding layer that hid what each test needs.

## Change

`_tests/` is now one recursive tree with a single orchestrator.

```
_tests/
  test.sh                 recursive orchestrator (the only entry point)
  run-one.sh              runs a single folder
  how-to-test.md          the contract for every test
  e2e/<group>/<test>/
    test.sh               shell test (optional)
    <name>_test.go        Go test, package tests (optional)
    www/…                 real input files, if any
```

- **Go and shell are equal.** `test.sh` discovers every folder with a `test.sh` or a `*_test.go`, runs each with its own folder as cwd, and runs them all in parallel. Success = exit 0.
- **One test = one folder, standalone.** `_tests/fixtures` and `dreegotest.Fixture`/`ServeFixture` are gone. A test writes its own project (or uses `dreego new`, whose template comes from the CLI binary). No shared template system.
- **Gates are ordinary tests.** layering, core-deps, no-binaries, coverage, fuzz and the release-prep contract live under `_tests/e2e/invariants/` and `_tests/e2e/release/`.
- **CI deduplicated.** `pull-request-check` runs `task test` once (the duplicate `go test`, coverage and fuzz steps are removed); `main-push` runs it once instead of twice.

## Result

- Full suite: 154 folders, green, **~42s** locally (was ~238s for the same coverage).
- `task test` builds the CLI once and installs the TypeScript compiler once for the whole tree.
