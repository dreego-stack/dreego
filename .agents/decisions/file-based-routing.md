# File-based Routing with Chi

**Date:** 2026-07-28
**Status:** Accepted (extended by [routing-and-components](routing-and-components.md))

## Context

Modern frameworks (Next.js, SvelteKit, Nuxt) use file-based routing: The directory structure determines the URL structure.

Dreego should also support this — but Go-idiomatically.

## Decision

**File-based routing via code generation, not via runtime scanning.**

```
routes/
├── get.dreego           →  /
├── about.dreego           →  /about
└── users/
    └── [id].dreego        →  /users/:id
```

`dreego generate` scans the `routes/` directory and generates a `dreego_router.go`:

```go
// CODE GENERATED BY DREEGO. DO NOT EDIT.
func RegisterDreegoRoutes(mux *http.ServeMux) {
    mux.HandleFunc("/", RenderIndexPage)
    mux.HandleFunc("/about", RenderAboutPage)
    mux.HandleFunc("/users/{id}", RenderUsersPage)
}
```

## Rationale

1. **Maximum performance:** No `filepath.WalkDir` at runtime
2. **Single binary:** No filesystem access needed
3. **Compile-Time Safety:** Non-existent routes break `go build`
4. **Type safety:** Route parameters are generated as typed Go variables

## Nested Layouts

```
routes/
├── layout.dreego          → Main wrapper (Navbar, Footer)
├── get.dreego           → Uses layout.dreego
└── admin/
    ├── layout.dreego      → Extends main layout with admin sidebar
    └── settings.dreego    → Uses admin/layout.dreego
```

Layouts are automatically cascaded (like in SvelteKit).

## Consequences

- `dreego generate` must parse the `routes/` directory
- Layout files (`layout.dreego`) are handled specially
- Dynamic segments: `[param]` → `{param}`, `[...catchall]` → `{catchall}`
- The generated router file is not committed
